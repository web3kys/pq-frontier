每个迁移项目失败的方式都差不多：不是算法换错了，而是换到一半才发现还有三十个没人知道的系统在用 RSA。盘点（inventory）是迁移的第一公里，也是唯一不能跳过的一步。它的交付物叫 **CBOM**——Cryptography Bill of Materials，密码物料清单。

## CBOM 记什么

CBOM 沿用软件物料清单 SBOM 的生态，格式以 CycloneDX 为准（其 cryptography 扩展定义了 `cryptoProperties`）。每条资产至少记：

| 字段 | 例 |
|---|---|
| 资产类型 | 算法 / 协议 / 证书 / 密钥 / 库 |
| 算法与参数 | RSA-2048、ECDH P-256、TLS 1.2 |
| 所在位置 | 系统、服务、代码仓库、文件路径 |
| 用途 | 密钥交换 / 签名 / 静态加密 / 传输加密 |
| 数据保质期 | 这批数据需要保密多少年 |
| 证书到期日 | 证书类资产必填 |
| 负责人 | 能拍板改造的团队 |

没有"数据保质期"这一列的盘点是残缺的——它直接决定优先级（见本站《迁移路线图》中的 Mosca 不等式）。

## 五路盘点法

1. **代码与依赖扫描**：在代码库里搜密码 API 调用（`Cipher.getInstance`、`crypto.createSign`、OpenSSL 命令行），并解析依赖树里的密码库（Bouncy Castle、OpenSSL、libsodium 的版本）。现成工具如 CBOMkit、Sonar 的密码扫描插件可以自动产出 CycloneDX 格式的草稿；
2. **证书与密钥库**：导出所有 CA 签发记录、TLS 终端证书、代码签名证书、SSH 主机密钥、HSM 里的密钥清单——证书是最好盘的资产，因为它们自带结构化字段；
3. **网络观测**：在网关与负载均衡上统计实际协商的 TLS 版本与套件分布。配置里"支持"的不等于流量里"在用"的，观测数据负责纠偏；
4. **配置与基础设施**：VPN、数据库加密、备份加密、磁盘加密、消息队列的 TLS 设置——这类"看不见的密码"最容易漏；
5. **供应商与 SaaS**：给关键供应商发问询：你们的 PQC 路线图是什么？数据在你们那里的加密方式是什么？把回复存档，这本身就是合规证据。

## 从清单到优先级

盘点完不是按清单顺序逐个换，而是打分排序。三个维度足够：**数据保质期**（≥10 年的先动）、**暴露面**（互联网可达的先动）、**改造难度**（库升级能解决的先动、要改协议的后排）。第一象限永远是：对外 TLS（先上混合密钥交换，见本站教程）与长寿命签名（固件、根证书）。

最后一条纪律：**CBOM 是活文档**。把它接入 CI 与证书自动化：新证书签发自动登记，新依赖引入自动扫描。只做一次性的 Excel 盘点，三个月后它就是历史文物了。盘点的终点不是一张表，而是组织第一次对"我们的密码用在哪"这个问题有了持续、可信的答案——迁移、审计、合规都会从这份答案里取数。
